- Added `services/local-demo-api`, a dependency-free Node.js learning adapter. It is not one of the 25 target Spring Boot services and has no authentication or local database. Compose connects metadata reads and registration to the Spring registry and telemetry submissions to the telemetry-ingestion service; alert and workflow projections remain in process memory.
- Implemented liveness/readiness, paginated vehicle reads, telemetry validation and event-ID idempotency, vehicle status/battery/range projection, diagnostic alerts and notifications, activity, conflict-safe simulated maintenance bookings, and idempotent payment outcome simulation against one illustrative invoice.
- Connected fleet portal startup vehicle reads, vehicle registration, telemetry simulation, maintenance booking, and notification-panel state to the local API. Compose proxies registration to the registry and telemetry events through the Kafka outbox and status consumer; standalone mode uses API memory, and the UI falls back to browser-only registration if the API is offline. The customer portal remains browser-local with a versioned demo store.
- Connected fleet billing to the local payment simulator. Success marks its synthetic invoice paid; failure and retry remain deterministic, and attempts are idempotent.
- Local API tests pass (18/18), fleet domain tests pass (5/5), customer demo-state tests pass (5/5), both portal production builds and `node scripts/dev.mjs --smoke` passed earlier. Compose config, service-catalog validation, Kustomize rendering, and Terraform formatting pass. HTTP bridge tests use local fake services; Compose and PostgreSQL runtime behavior remain unverified because Docker is unavailable.
